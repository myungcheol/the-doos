# 요구사항

합의일: 2026-11-18. 사용자의 대화 지시를 기준으로 하며, 변경 이유는 [결정 기록](decisions.md)에 남긴다.

## 목적과 범위

- 1987년 두릉두씨세보의 세로쓰기 판독 방법을 조사하고 근거·예외와 함께 Markdown으로 문서화한다.
- 해당 규칙을 PaddleOCR 기반 처리 프로그램으로 구현한다. 실행 중 LLM API, 로컬 LLM, VLM을 사용하지 않는다.
- 입력은 `scan/genealogy`의 파일 하나 또는 여러 개다. `scan/frontmatter`는 자동 OCR 대상에서 제외한다.
- `scan/frontmatter`는 본문 OCR 규칙을 위한 사례 조사에서도 제외한다. 사례는 `scan/genealogy`에서 확보한다.
- 이름, 부가 정보, 족보상의 부모·자녀 연결을 PostgreSQL에 저장한다.
- Node.js·Next.js로 관리자 검수 화면과 일반 열람 화면을 제공한다.
- 스캔과 미검수 결과를 포함한 모든 자료는 공개한다. 검수 상태는 표시한다.
- 관리자는 사용자 한 명이며, 공개 열람과 관리자 편집 권한을 구분한다.

## 데이터와 판독

- 한자 원문, 독음 후보, 확정 독음을 구분한다. 이름이 같다는 이유로 인물을 합치지 않는다.
- 출생·사망·관직·학력·배우자·묘소 등과 아직 분류하지 못한 부가 정보를 보존한다.
- 인물의 부가 정보는 그 인물 이름 왼쪽에 오는 내용이다. 이름의 오른쪽·위쪽 텍스트를 해당 인물 정보로 귀속하지 않는다.
- A의 배우자 B·C에 대한 설명은 A의 부가 정보로 보존한다. B·C를 각각 인물 테이블에도 저장하고 A–B, A–C 혼인 관계를 별도로 연결한다. 설명 원문과 배우자 인물·혼인 레코드를 참조로 연결해 중복 편집을 피한다.
- 配는 우선 배우자로 인식한다. 해당 배우자 설명에서 妾(첩)이 발견되면 첩으로 분류한다. 첩 표기가 없다는 이유만으로 본부인으로 확정하지 않는다.
- 女/女 뒤 세 글자는 사위 성명, 두 글자는 두씨집안 딸 이름으로 처리한다. 글자 수 판독이 불명확하면 미검수으로 남긴다.
- `女` 뒤 세 글자의 경우 이름 미상 딸과 사위 후보를 만들고 검수 후 혼인 관계를 설정한다. 두 글자의 경우 딸 인물 후보를 만든다. 사위 이름을 딸 이름으로 쓰지 않는다.
- `xx人`은 본관이 xx인 상대와 결혼했다는 부기다. 상대 이름은 만들지 않고 본관만 보존한다. `人`만 있으면 본관 미상으로 무시한다.
- 한국어 풀이는 인식한 정형 항목을 사전·규칙·문장 틀로 생성한다. 자유로운 한문 서술 전체의 자동 번역은 범위 밖이다.
- 해석하지 못한 부분은 원문으로 남기고, 관리자가 풀이를 입력·수정할 수 있게 한다.
- 고려 왕대·고려 자체 연호·고려와 관련된 중국 연호·조선 왕대와 연호의 왕/연호/서기 대응 자료를 조사·관리하고 생몰년 환산에 사용한다. 조선 기록에 쓰인 중국 연호도 포함한다.
- 연호·왕대·간지·음양력·윤달 등 원문을 보존한다. 즉위년·원년·복위와 동명 왕/연호를 구분하고 근거가 모호한 연도는 후보로 남긴다.
- 연도만 있는 날짜는 월=1·일=1, 연·월만 있는 날짜는 일=1로 보충한다. `month_assumed`, `day_assumed`, 원문 정밀도를 저장한다. 연도 자체는 임의로 채우지 않는다.
- 서기 연도 환산과 음력→양력 변환은 구분한다. 서기 연도와 원문의 월·일(없는 부분은 1)을 조합한 정규화 값은 역법과 변환 상태를 동반하며, 실제 양력 날짜로 잘못 표시하지 않는다. 상세 필드와 예시는 [날짜 규칙](research/date-normalization.md)을 따른다.
- 모든 추출 정보와 관계에는 근거 페이지·영역을 연결한다. 좌표는 향후 확대·축소 표시가 가능해야 한다.
- 원본 스캔, OCR 출력, 규칙의 해석 결과, 사람이 수정한 값을 구분한다.
- 재처리해도 검수한 값을 덮어쓰지 않는다. 모델·사전·규칙 버전과 실행 이력을 남긴다.
- 글자 인식의 확신도와 관계 판독의 상태를 구분한다. 미상·미연결을 정상 상태로 표현한다.

## 계보와 탐색

- 탐색에 사용하는 연결은 족보에 기록된 부모·자녀 관계다. 부모는 남성으로 제한하지 않는다.
- A의 배우자가 B이고 자녀가 C와 D이면, 책의 연결에 따라 A→C와 A→D를 저장한다.
- B가 배우자라는 이유만으로 B→C와 B→D를 생성하지 않는다.
- D의 자녀 E가 기록되어 있으면 D→E를 저장한다.
- 자녀 한 명은 같은 열 바로 윗단 인물과 연결한다. 여럿이면 오른쪽부터 아들 나이순, 이어 딸 나이순으로 읽는다. A의 첫째 딸 B·둘째 아들 C·셋째 아들 D는 왼쪽부터 B D C로 배치된다.
- 바로 윗단이 비면 그 윗단 오른쪽의 첫 인물을 부모로 찾는다. 같은 쪽에 없으면 계보가 이어지는 쪽까지 추적한다. 관계의 근거·적용 규칙·검수 상태를 기록한다.
- 배우자(사위)로 확정된 女 항목은 그 사위 본인을 두씨 부모의 친자녀로 연결하지 않는다. 딸 인물과의 혼인 관계로 표현하고 계보상의 출현 위치를 보존한다.
- 친생·입양 등 명시된 관계 정보는 보존하되, 어느 연결을 계보 탐색에 사용할지는 책의 표기와 검수에 따른다.
- 선조 탐색: 선택 인물을 아래에 두고 부모를 위에 표시한다. 부모 선택 시 그 부모의 부모를 한 단계 더 펼친다.
- 후손 탐색: 선택 인물을 뿌리로 두고 자녀를 아래에 표시한다. 자녀 선택 시 그 자녀들을 한 단계 더 펼친다.
- 잘못된 자기 참조·순환 연결은 저장 시 막고, 조회에서도 무한 탐색을 방지한다.

## 화면

- 검수: 스캔과 OCR·구조화 결과를 함께 보며 인물·부가 정보·배우자·관계를 추가, 수정, 삭제한다.
- 인물 선택 영역도 수정할 수 있어야 한다. 수정·삭제 기록과 근거를 보존한다.
- 女 항목은 딸/배우자 판정과 연결할 인물·혼인을 검수한다. 생몰 정보는 자동 보충한 월·일을 명확히 구분해 수정할 수 있다.
- 일반 열람: 책 순서대로 페이지 이동·확대, 페이지 속 인물 선택, 상세 정보, 선조·후손 탐색을 제공한다.
- 검색: 한자 이름과 한글 독음으로 인물을 찾고 해당 스캔 페이지·영역으로 이동한다. 후보 독음은 확정 독음과 구분한다.
- 한 인물이 여러 쪽에 걸쳐 등장할 수 있으며, 각각의 출현 위치를 보존한다.

## 운영과 검증

- 우선 로컬에서 Docker Compose로 PostgreSQL을 실행한다.
- OCR 작업과 웹 서비스는 분리한다. 서버 배포 후에도 로컬 OCR 결과를 옮길 수 있게 한다.
- 무료 호스팅은 배포 단계에서 저장 용량, 이미지 제공, DB, 인증 조건을 확인한 뒤 결정한다.
- 서로 이어지는 대표 페이지로 전체 흐름을 확인한 뒤 전체 본문으로 확대한다.
- 파일 번호가 빈 것은 해당 페이지의 스캔이 없기 때문이다(사용자 확인). 누락 페이지를 목록에 표시하고 누락을 가로질러 관계를 추측 확정하지 않는다.
- OCR 문자 오류, 인물 분리 오류, 관계 연결 오류를 각각 측정한다. 목표 수치는 첫 표본 평가 뒤 정한다.
- 주요 검증 사례: 페이지 간 동일 인물, 동명이인, 여러 배우자, 딸의 자녀, 재실행 후 수정 보존, 순환 연결 거부.

## 아직 정하지 않은 사항

- 대표 표본의 최종 구성, 실제 사례별 판독 정답, OCR 모델·버전과 CPU/GPU 실행 조건.
- 페이지를 넘는 연결 표기와 입양의 세부 처리, 사용자가 설명한 배치 규칙의 예외 사례.
- 독음 사전의 고정 버전·배포 조건, 관리자 인증 방식, 배포 서비스.

위 사항은 관련 티켓에서 근거를 확인하고 결정한다. 미정 항목을 자동으로 사용자 승인 대기로 취급하지 않는다.
