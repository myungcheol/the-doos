# 티켓

## 운영 방식

- 한 티켓은 하나의 리뷰 가능한 결과를 만든다. 상태는 `대기` → `진행` → `리뷰 대기` → `완료`다.
- **사용자가 산출물을 확인하고 OK하면 완료로 바꾼다.** 수정 요청이 오면 수정·재검증 후 리뷰 대기로 둔다.
- 원칙적으로 한 번에 하나를 진행한다. 리뷰 중인 산출물 보완과 관련 계획 수정은 함께 기록한다.
- 모든 티켓의 설명·범위·산출물·완료 조건·검증을 아래 상세에 작성했다. 선행 관계와 상태는 이 목록을 기준으로 한다.
- 보통 수작업 변경 100~300줄을 목표로 한다. 강제 한도는 아니며 독립 동작이 여럿이거나 대응표가 커지면 착수 전에 나눈다.
- 표에 나온 산출물 경로는 계획이며, 파일이 생기기 전에는 링크로 표시하지 않는다.
- 관련 검증·문서만 같은 변경에 넣고 [진행 이력](progress.md)에 시점·티켓·변경·검증·남은 일을 기록한다.
