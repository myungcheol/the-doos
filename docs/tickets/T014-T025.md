# T014~T025 상세

상태와 선행 관계는 [티켓 원장](../tickets.md)을 따른다. 아래는 계획이며 구현 완료를 뜻하지 않는다.

<a id="t014"></a>

## T014 — 로컬 PostgreSQL Compose

- 설명: 지속되는 로컬 DB 실행 기반을 만든다.
- 범위: DB 컨테이너·볼륨·환경 변수 예시·상태 확인. 웹·OCR 컨테이너화는 제외한다.
- 산출물: Compose 파일, 비밀값 없는 설정 예시, 운영 안내.
- 완료 조건: 로컬 시작·중지·재시작 후 데이터가 유지된다.
- 검증: 임시 데이터로 재시작·연결을 확인하며 기존 볼륨 삭제 없이 검증한다.

<a id="t015"></a>

## T015 — 페이지·OCR 실행·영역 스키마

- 설명: 스캔과 추출 결과의 출처를 저장한다.
- 범위: 페이지·원본 파일·누락 상태·OCR 실행·영역 테이블. 인물·관계 테이블은 제외한다.
- 산출물: 마이그레이션, 데이터 사전, DB 검증 fixture.
- 완료 조건: 이미지 크기·좌표·모델 버전·실행 식별자를 저장하고 여러 실행을 구분한다.
- 검증: 마이그레이션 적용과 롤백, 원본 좌표 왕복, 한 쪽의 여러 실행 저장을 검증한다.

<a id="t016"></a>

## T016 — 인물·출현·부가 정보 스키마

- 설명: 한 인물의 여러 출현과 원문·구조화 사실을 연결한다.
- 범위: 인물, 출현, 확정/후보 독음, 일반 사실, 부분 날짜, 女 검수 상태. 혼인 스키마는 T039다.
- 산출물: 마이그레이션, 필드 설명, 저장 fixture.
- 완료 조건: 이름 미상·동명이인·여러 출현과 날짜 보충 flag를 저장한다. 배우자 설명도 A의 부가 정보로 남길 수 있다.
- 검증: 같은 이름의 별도 인물, 여러 쪽, 월일 미상과 실제 1월1일, 음력 구성요소를 왕복 검증한다.

2026-11-21 논의 반영: T015와 함께 구현하며 출현은 책 속 원본 위치로 저장하고 실행별 근거를 별도 연결한다. 날짜 열은 `person_facts`에 포함한다. T038 완료 전에도 부분 날짜·보충 flag 저장 구조를 만들 수 있으며 실제 서기 환산 계산은 T038에 남긴다.

<a id="t017"></a>

## T017 — 계보 연결과 한 단계 조회

- 설명: 선조·후손 탐색에 사용할 명시적 방향 관계를 저장한다.
- 범위: 부모→자녀 테이블, 관계 근거, 한 단계 조회, 순환 방지. 혼인·트리 화면은 제외한다.
- 산출물: 마이그레이션, 조회 함수, 무결성 검증.
- 완료 조건: 여성 부모와 미연결 상태를 허용하며 배우자라는 이유로 자녀 연결을 만들지 않는다.
- 검증: A→C/A→D/D→E, 자기 참조·여러 단계 순환 거부, 양방향 한 단계 조회를 검사한다.

<a id="t018"></a>

## T018 — 수정·삭제 이력과 현재 값 선택

- 설명: 재처리 때문에 검수 결과가 사라지지 않게 한다.
- 범위: 현재값 직접 갱신·수동 검수 행 보호·변경 이력·논리 삭제와 관계 처리. 편집 UI는 제외한다.
- 산출물: 수정 이력 스키마, 현재 값 조회 규칙, 삭제 정책.
- 완료 조건: 최초 판독과 수정 이력을 보존하고, 검수한 현재값과 삭제 상태를 재처리가 덮어쓰지 않는다.
- 검증: 수정 후 재처리, 삭제 후 재적재, 연결된 인물 삭제의 참조 무결성을 검사한다.

2026-11-21 구현 범위: 인물·사실의 현재값 직접 수정과 이력, 논리 삭제, 기존 인물·출현·독음·사실·계보 변경 이력과 현재 인물/사실·선조/후손 조회를 구현한다. 혼인 테이블의 이력 연결은 T039에서 추가한다. 재적재는 같은 책 속 출현 ID를 재사용해야 하며 실제 파일 매칭·적재는 T019에서 검증한다.

<a id="t019"></a>

## T019 — 단일 파일 DB 적재

- 설명: 한 파일의 추출 결과를 일관되게 저장한다.
- 범위: 페이지·인물·정보·배우자 인물/혼인·계보 적재. 다중 파일 스케줄링은 제외한다.
- 산출물: 적재 명령/서비스, 트랜잭션 처리, 실행 안내.
- 완료 조건: 원문 참조와 A–B/A–C 혼인이 저장되고 재적재 중복·수정 덮어쓰기가 없다.
- 검증: 같은 파일 재실행, 중간 실패 롤백, 수동 수정 후 재실행, 미해결 페이지 참조를 검증한다.

2026-11-23 착수 범위: T039 혼인 스키마를 사용한다. T038의 원문 연·월·일, 환산 상태, 후보와 보충 표시를 함께 적재한다. 실행 및 검수는 [단일 페이지 적재 안내](../../db/import-page.md)를 따른다.

<a id="t020"></a>

## T020 — 여러 파일 처리와 재시도

- 설명: 사용자가 지정한 여러 스캔을 반복 처리할 수 있게 한다.
- 범위: 파일 목록 입력·진행 기록·실패 분리·재시도. 웹 작업 큐는 제외한다.
- 산출물: 다중 입력 CLI, 실행 요약, 재시도 안내.
- 완료 조건: 일부 실패해도 성공 건을 식별하고 실패 건만 다시 실행할 수 있다.
- 검증: 정상/손상/없는 파일 혼합, 중단 후 재실행, 성공 건 중복 생성 방지를 검사한다.

<a id="t021"></a>

## T021 — Next.js 기반과 관리자 인증

- 설명: 공개 열람과 사용자 한 명의 편집 권한을 구분한다.
- 범위: 앱 기본 구조·DB 연결·인증·서버 쓰기 권한 검사. 검수 기능 화면은 제외한다.
- 산출물: Next.js 앱 기반, 인증 설정 예시, 권한 검증.
- 완료 조건: 로그인하지 않아도 읽을 수 있고 쓰기는 관리자만 가능하다.
- 검증: 비로그인 직접 API 쓰기 거부, 로그인/로그아웃, 세션 만료를 검증한다.

<a id="t022"></a>

## T022 — 검수 화면 읽기

- 설명: 수정 전에 스캔과 기계 판독 결과를 나란히 확인한다.
- 범위: 페이지 선택·이미지·영역 강조·원문·정보·검수 상태. 저장 동작은 제외한다.
- 산출물: 검수 조회 화면과 읽기 API.
- 완료 조건: 영역 선택 시 올바른 인물·출현의 자료를 보여준다.
- 검증: 같은 이름의 여러 인물, 여러 OCR 실행, 빈 단, 누락 페이지 표시를 확인한다.

<a id="t023"></a>

## T023 — 인물과 부가 정보 편집

- 설명: 검수자가 이름과 사실을 직접 바로잡는다.
- 범위: 추가·수정·삭제와 독음/풀이/생몰 및 보충 flag 편집. 관계·영역 편집은 제외한다.
- 산출물: 편집 API와 폼, 변경 이력 표시.
- 완료 조건: 관리자 수정이 저장·재조회에 반영되고 원문/기계 결과는 유지된다.
- 검증: 이름 수정, 이름 미상 추가, 부분 날짜 보충값을 실측값으로 변경, 삭제 후 재조회와 쓰기 권한을 확인한다.

<a id="t024"></a>

## T024 — 배우자와 계보 관계 편집

- 설명: 잘못 추출한 연결을 관리자가 수정한다.
- 범위: 기존 인물 선택·혼인/부모 관계 추가·수정·삭제. 女 판정 흐름은 T040이다.
- 산출물: 관계 편집 API와 폼.
- 완료 조건: 배우자 지위·혼인 연결과 부모 연결을 별개로 수정하고 근거를 남긴다.
- 검증: A–B/A–C와 A→D/D→E 편집, 배우자 연결 후 자녀 자동 생성 없음, 순환 거부를 확인한다.

<a id="t025"></a>

## T025 — 인물 영역과 출현 연결 편집

- 설명: 스캔의 클릭 위치와 인물 소속 오류를 수정한다.
- 범위: 영역 이동·크기 수정·출현을 다른 인물에 연결. 전역 인물 병합/분리는 제외한다.
- 산출물: 영역 편집 UI/API와 원본 좌표 저장.
- 완료 조건: 확대율이 달라도 동일한 원본 위치에 저장되고 잘못 연결된 출현을 정정한다.
- 검증: 여러 확대율·이미지 크기·경계 좌표·출현 재연결 후 상세 표시를 확인한다.
