# T014~T025 상세

상태와 선행 관계는 [티켓 원장](../tickets.md)을 따른다. 아래는 계획이며 구현 완료를 뜻하지 않는다.

<a id="t014"></a>

## T014 — 로컬 PostgreSQL Compose

- 설명: 지속되는 로컬 DB 실행 기반을 만든다.
- 범위: DB 컨테이너·볼륨·환경 변수 예시·상태 확인. 웹·OCR 컨테이너화는 제외한다.
- 산출물: Compose 파일, 비밀값 없는 설정 예시, 운영 안내.
- 완료 조건: 로컬 시작·중지·재시작 후 데이터가 유지된다.
- 검증: 임시 데이터로 재시작·연결을 확인하며 기존 볼륨 삭제 없이 검증한다.

<a id="t015"></a>

## T015 — 페이지·OCR 실행·영역 스키마

- 설명: 스캔과 추출 결과의 출처를 저장한다.
- 범위: 페이지·원본 파일·누락 상태·OCR 실행·영역 테이블. 인물·관계 테이블은 제외한다.
- 산출물: 마이그레이션, 데이터 사전, DB 검증 fixture.
- 완료 조건: 이미지 크기·좌표·모델 버전·실행 식별자를 저장하고 여러 실행을 구분한다.
- 검증: 마이그레이션 적용과 롤백, 원본 좌표 왕복, 한 쪽의 여러 실행 저장을 검증한다.

<a id="t016"></a>

## T016 — 인물·출현·부가 정보 스키마

- 설명: 한 인물의 여러 출현과 원문·구조화 사실을 연결한다.
- 범위: 인물, 출현, 확정/후보 독음, 일반 사실, 부분 날짜, 女 검수 상태. 혼인 스키마는 T039다.
- 산출물: 마이그레이션, 필드 설명, 저장 fixture.
- 완료 조건: 이름 미상·동명이인·여러 출현과 날짜 보충 flag를 저장한다. 배우자 설명도 A의 부가 정보로 남길 수 있다.
- 검증: 같은 이름의 별도 인물, 여러 쪽, 월일 미상과 실제 1월1일, 음력 구성요소를 왕복 검증한다.

2026-11-21 논의 반영: T015와 함께 구현하며 출현은 책 속 원본 위치로 저장하고 실행별 근거를 별도 연결한다. 날짜 열은 `person_facts`에 포함한다. T038 완료 전에도 부분 날짜·보충 flag 저장 구조를 만들 수 있으며 실제 서기 환산 계산은 T038에 남긴다.

## T017 — 계보 연결과 한 단계 조회

- 설명: 선조·후손 탐색에 사용할 명시적 방향 관계를 저장한다.
- 범위: 부모→자녀 테이블, 관계 근거, 한 단계 조회, 순환 방지. 혼인·트리 화면은 제외한다.
- 산출물: 마이그레이션, 조회 함수, 무결성 검증.
- 완료 조건: 여성 부모와 미연결 상태를 허용하며 배우자라는 이유로 자녀 연결을 만들지 않는다.
- 검증: A→C/A→D/D→E, 자기 참조·여러 단계 순환 거부, 양방향 한 단계 조회를 검사한다.

## T018 — 수정·삭제 이력과 현재 값 선택

- 설명: 재처리 때문에 검수 결과가 사라지지 않게 한다.
- 범위: 현재값 직접 갱신·수동 검수 행 보호·변경 이력·논리 삭제와 관계 처리. 편집 UI는 제외한다.
- 산출물: 수정 이력 스키마, 현재 값 조회 규칙, 삭제 정책.
- 완료 조건: 최초 판독과 수정 이력을 보존하고, 검수한 현재값과 삭제 상태를 재처리가 덮어쓰지 않는다.
- 검증: 수정 후 재처리, 삭제 후 재적재, 연결된 인물 삭제의 참조 무결성을 검사한다.

2026-11-21 구현 범위: 인물·사실의 현재값 직접 수정과 이력, 논리 삭제, 기존 인물·출현·독음·사실·계보 변경 이력과 현재 인물/사실·선조/후손 조회를 구현한다. 혼인 테이블의 이력 연결은 T039에서 추가한다. 재적재는 같은 책 속 출현 ID를 재사용해야 하며 실제 파일 매칭·적재는 T019에서 검증한다.

## T021 — 소셜 로그인과 사용자·관리자 권한

- 설명: 공개 열람, 일반 사용자의 수정 제안, 관리자 한 명의 자료 수정·승인을 지원할 인증 기반을 만든다. 기존 Next.js 앱과 DB 연결을 확장한다.
- 범위: 소셜 가입·로그인·로그아웃, 계정과 세션 저장, 관리자 지정, 서버 권한 검사. 인물·관계 직접 편집은 T023·T024에서 연결하고 수정 요청·승인 화면과 API는 [T021-01~03](T021-requests.md)에서 구현한다.
- 산출물: 로그인 UI, 인증 라이브러리 연동, 계정·소셜 연결·세션 마이그레이션, 관리자 지정 명령, 제공자별 설정 안내, 권한 검증.
- 완료 조건: 방문자는 로그인 없이 족보를 읽는다. 소셜 첫 로그인은 일반 사용자로 등록되고 재로그인은 같은 계정으로 연결된다. 관리자 권한은 운영자가 명시적으로 지정한다. 서버의 권한 검사로 일반 사용자의 직접 자료 변경과 관리자 기능 호출을 거부한다.
- 검증: 첫 로그인/재로그인, 로그인 취소·실패, 로그아웃·세션 만료 후 접근, 쿠키 변조, 비로그인·일반 사용자의 직접 쓰기 요청 거부, 관리자 권한 확인을 검사한다. 제공자별 실제 로그인도 확인한다.

### 로그인과 계정 구조

구글·페이스북·카카오·네이버를 연동 대상으로 둔다. 제공자의 로그인 결과를 서버에서 검증한 뒤 우리 서비스의 계정과 세션을 생성한다. 인증 라이브러리는 착수 시 네 제공자와 현재 Next.js 버전의 지원을 확인해 선택한다.

| 데이터 | 역할 |
|---|---|
| `users` | 내부 사용자 ID, 표시 이름, `member` 또는 `admin` 권한 |
| `user_accounts` | 제공자와 제공자의 고유 사용자 ID를 내부 사용자 ID에 연결. 제공자·식별자 조합은 유일해야 한다. |
| `sessions` | 로그인 계정, 세션 식별 정보, 만료와 무효화 상태 |

이메일이 같아도 서로 다른 소셜 계정을 자동으로 합치지 않는다. 추가 계정 연결은 기존 계정으로 로그인한 상태에서 새 제공자의 인증을 완료해야 한다. 이메일이 제공되지 않아도 제공자의 고유 식별자로 로그인할 수 있다. 관리자도 소셜 계정을 사용하며 첫 가입자에게 자동으로 관리자 권한을 주지 않는다.

세션은 로그아웃하면 즉시 무효화한다. 만료 시간은 설정값으로 관리하며 8시간은 논의 중인 기본값 제안이다. 쿠키 보호, 위조 요청 방지, 로그인 요청 제한을 인증 경계에 적용한다. 변경 이력의 작업자는 서버가 확인한 사용자 ID에서 정한다.

### 권한과 후속 수정 요청 흐름

| 역할 | 허용 작업 |
|---|---|
| 방문자 | 공개 족보·스캔 열람과 검색 |
| 일반 사용자 | 수정 요청 제출, 자기 요청의 상태 확인 |
| 관리자 | 자료 직접 수정, 요청 검토·승인·반려 |

후속 기능은 사용자가 대상 인물·사실·관계와 제안값, 이유, 근거를 제출하고 관리자가 승인하는 흐름이다. `change_requests`에 요청자·상태·처리자를, `change_request_items`에 대상·요청 당시 값·제안값을 저장하는 구조를 계획한다. 요청 하나에 여러 항목을 포함할 수 있다.

승인 시 요청 당시 값과 현재값을 비교한다. 이미 다른 검수로 변경된 항목은 충돌을 표시해 다시 판단한다. 실제 자료 수정과 승인 상태 변경은 한 트랜잭션으로 처리하고, 기존 변경 이력에 요청자·승인자·요청 ID를 연결한다. 요청 반려와 족보 자료의 거절 상태는 별도로 관리한다.

### 구현 순서와 외부 설정

리뷰 단위는 공통 계정·세션과 권한 검사, 제공자별 로그인 연결 순서로 나눈다. 네 제공자의 연동 순서는 착수 때 정한다. 개발자 앱 등록, 클라이언트 자격증명, 로그인 복귀 주소, 동의 화면 설정이 필요하다. 공개 서비스 전 제공자별 검수·공개 전환 조건도 확인하며 자격증명은 저장소에 넣지 않는다.

공식 설정 근거는 [구글](https://developers.google.com/identity/openid-connect/openid-connect), [페이스북](https://developers.facebook.com/docs/facebook-login/v2.0), [카카오](https://developers.kakao.com/docs/ko/kakaologin/prerequisite), [네이버](https://developers.naver.com/docs/login/devguide/devguide.md)다. 네이버는 공개 로그인 전에 사전 검수를 신청한다. 실제 연동 검증 전에는 해당 제공자를 완료로 표시하지 않는다.

## T025 — 인물 영역과 출현 연결 편집

- 설명: 스캔의 클릭 위치와 인물 소속 오류를 수정한다.
- 범위: 영역 이동·크기 수정·출현을 다른 인물에 연결. 전역 인물 병합/분리는 제외한다.
- 산출물: 영역 편집 UI/API와 원본 좌표 저장.
- 완료 조건: 확대율이 달라도 동일한 원본 위치에 저장되고 잘못 연결된 출현을 정정한다.
- 검증: 여러 확대율·이미지 크기·경계 좌표·출현 재연결 후 상세 표시를 확인한다.
