위 표의 연도 범위만으로 개원 연도 전체의 날짜를 유효하다고 판정하지 않는다. 연도 중간의 개원·교체일은 별도 검증한다.
조선의 왕 이름+재위년은 연호 이름과 다른 체계이므로 검색 키를 분리한다.
원년이 확인된 연속 구간에서만 `원년의 서기 연도 + 기년 - 1`을 사용한다. 즉위년·복위·중원 등은 별도 구간으로 조회한다.
왕 이름이 같아도 왕조가 다르면 다른 항목이며, 간지와 연호 결과가 충돌하면 자동 확정하지 않는다.

## 저장해야 할 정보

최종 SQL 필드 이름은 스키마 티켓에서 정하되 다음 의미는 유지한다.

| 정보 | 의미 |
|---|---|
| 원문·근거 영역 | 원래 날짜 표현과 스캔 위치 |
| 사건 종류 | 출생·사망 등. 묘소·이장 날짜와 구분 |
| 왕조·왕·연호·기년·구간 | 왕대/연호 구분, 즉위/원년/복위 및 조회 항목 ID |
| 원문 연·월·일과 정밀도 | 연만 / 연월 / 연월일. 없는 월·일은 원문 필드에서 NULL |
| 역법·윤달 | 양력 / 음력 / 미상, 윤달 여부 true / false / 미상 |
| 서기 연도·정규화 월·일 | 서기 연도 대응 결과, 없는 월·일만 1로 보충한 구성요소 |
| `month_assumed`, `day_assumed` | 각각 자동 보충 여부. 원문에 실제 1월/1일이 있으면 false |
| 환산 상태·근거·버전 | 확정 / 후보 여러 개 / 대응 없음 / 범위 밖 및 사용한 표의 버전 |
| 실제 양력 날짜와 달력 체계 | 별도 역법 변환이 성공했을 때만 저장. 보충값에서 변환했으면 그 출처도 유지 |

## 월·일 보충 예시

아래는 규칙 검증용 예시이며 특정 족보 인물의 실제 생몰일을 주장하지 않는다.

| 입력 | 정규화 서기 연·월·일 | month_assumed | day_assumed | 원문 정밀도 |
|---|---|---|---|---|
| 西紀一九六五年 | 1965 / 1 / 1 | true | true | 연 |
| 西紀一九六五年五月 | 1965 / 5 / 1 | false | true | 연월 |
| 西紀一九六五年一月一日 | 1965 / 1 / 1 | false | false | 연월일 |
| 至正十六年 | 1356 / 1 / 1 | true | true | 연 |
| 왕·연호 없이 간지만 있어 연도가 여러 후보임 | 연도 후보 각각에 월·일 보충 가능하나 확정 날짜는 없음 | 원문에 따름 | 원문에 따름 | 원문에 따름 |

보충된 1월 1일을 실제 생일·기일처럼 표시하지 않는다. 화면에서는 “1965년(월일 미상)”처럼 원문 정밀도를 우선한다.
월이 있는데 읽기 실패한 경우와 원래 월이 없는 경우도 구분한다. OCR 미판독을 누락으로 확정하지 않는다.

## 서기 연도 환산과 음양력 변환

서기는 연도 체계이고 양력은 달력 체계다. 음력 월·일에 서기 연도만 붙인 결과는 양력 날짜가 아니다.
따라서 사용자가 요청한 1월/1일 보충은 우선 원문 날짜의 정규화 구성요소에 적용하고, 실제 양력 변환은 별도 상태로 둔다.

- 원문 음력 2월 30일처럼 양력 DATE에 직접 넣을 수 없는 값은 구성요소로 보존한다.
- 윤달 미상은 임의로 평달로 바꾸지 않는다. 달력 변환 후보가 여러 개면 모두 보존한다.
- E8은 율리우스력과 그레고리력을 구분한다. 역사 자료의 “양력”을 전부 같은 역법으로 간주하지 않는다.
- DB DATE를 채우기 위해 유효하지 않은 값을 조용히 보정하지 않는다. 양력 변환 결과·정규화 구성요소·검색 정렬용 보충값을 혼동하지 않는다.
- 초기 구현 완료 조건은 왕대/연호→서기 연도 및 부분 날짜 처리다. 역사적 음양력의 정확한 일 단위 변환 엔진 선택은 별도 조사·범위 확정이 필요하다.

## T038 구현과 검수

[대응표](../../data/era-years.json)는 항목별 검색 표기, 원년, 끝년, 해당하는 경우 즉위년, 출처를 갖는다. 2026-11-23.1판의 범위는 위 초기 사례와 동명·복위 구간이다. T035~T037에서 표를 확장할 때 버전을 올린다.

OCR 후 인물 파서가 각 날짜에 [환산 함수](../../scripts/era_dates.py)를 적용한다. 기존 OCR JSON도 인물 파서를 다시 실행하면 적용된다. 아래 명령은 같은 파서에 전사문을 직접 입력한다.

```sh
.venv/bin/python scripts/information_parser.py --text '至正十六年丙申生'
.venv/bin/python scripts/information_parser.py --text '乾德元年卒'
.venv/bin/python scripts/information_parser.py --text '宋乾德元年卒'
.venv/bin/python scripts/information_parser.py --text '至正十六年甲辰生'
```

순서대로 1356년, 전촉·북송의 두 후보(919·963), 북송 963년, 간지 충돌이 나온다. 간지만 있으면 이 책의 검토 범위인 918~1987년에서 일치하는 해를 모두 제시한다. 원문 월·일은 그대로 두며, 판독 불가 표지(□月 등)가 있으면 해당 구성요소는 보충하지 않는다. 역법 표기가 없으면 미상으로 유지하며 윤달은 음력으로 읽는다.

`date_details`에는 표 버전, 조회 표기·기년, 대응 항목과 간지 대조 전후의 후보가 남는다. 미수록 왕대·연호는 서기 연도를 확정할 수 없으며, 미분류 원문과 날짜 조각이 따로 남을 수 있다. 전체 날짜의 양력 환산은 별도 작업이다.
