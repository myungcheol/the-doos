# 인명 한자 독음 자료 조사

## 2026-11-20 확인

- [대법원 전자가족관계등록시스템 인명용 한자 조회](https://efamily.scourt.go.kr/cs/CsBltnWrtList.do?bltnbordId=0000010)는 지정된 음과 허용된 동자·속자·약자를 제공한다. 페이지가 제공하는 [인명용 한자표 PDF](https://efamily.scourt.go.kr/downloads/etc/hanja.pdf)를 조사 자료로 받았다. SHA-256: `60c26021aa3dea8ec7fab3ab2d7736a472eb7c2bca8c327e4bd846253d4b17ea`. PDF가 현행 규칙 전체와 일치하는지와 재사용 조건은 추가 확인이 필요하다.
- [대법원 2024년 보도자료](https://lawclerk.scourt.go.kr/portal/news/NewsViewAction.work?gubun=6&seqnum=2642)에 따르면 2024년 인명용 한자가 추가되었다. 오래된 한자표를 최신판으로 가정하지 않는다.
- 고려·조선의 족보 한자는 현대 인명용 목록에 없을 수 있으므로 목록 밖 글자를 거부하거나 원문을 바꾸지 않는다. 별도 출처를 표시한 보충 자료 또는 미등록 상태가 필요하다.
- [Unicode Unihan](https://www.unicode.org/reports/tr38/)은 보충 가능 자료로 조사 중이다. 독음의 의미, 두음법칙·인명 예외, 이체자 처리 및 [이용 조건](https://www.unicode.org/license.txt)을 검토한 뒤에만 사용한다.
- 독음은 확정값이 아니라 출처별 후보로 보존한다. 실제 이름에서의 올바른 음은 검수로 확정해야 한다.
- PDF는 54쪽이며 첫 쪽 텍스트 추출을 시험했으나 한자와 독음이 추출되지 않았다. PDF의 표를 신뢰할 수 있게 기계 판독하거나 대법원의 다른 원천을 확보하는 과정이 필요하다.

## 사용자 제안 자료

- 사용자가 제안한 [나무위키 인명용 한자](https://namu.wiki/w/%EC%9D%B8%EB%AA%85%EC%9A%A9%20%ED%95%9C%EC%9E%90)는 직접 접근이 되지 않아, 검색 결과에 나타난 [별도 미러](https://namu.moe/w/%EC%9D%B8%EB%AA%85%EC%9A%A9%20%ED%95%9C%EC%9E%90)를 참고했다. 미러의 내용이 원문과 같은 시점인지는 확인하지 못했다.
- 그 자료는 한글 음별 한자 표와 함께 [Unicode 제출 문서](https://unicode.org/L2/L2020/20082-update-korean.pdf)를 안내한다. 미러의 설명상 문서 첨부파일에는 한자별 독음 목록이 있으나 2018년판에 기반한다. 2024년 추가분을 포함하는 현행 대법원 목록과는 별도로 버전을 확인해야 한다.
- 나무위키 문서의 기본 이용 조건은 [CC BY-NC-SA 2.0 KR](https://creativecommons.org/licenses/by-nc-sa/2.0/kr/)이다. 변환 JSON에 원문 URL·라이선스·변경 내용을 넣고 `data/README.md`에도 저작자표시·비영리·동일조건변경허락 조건을 기록한다. 법적 등록 가능 여부의 확정 원천으로는 사용하지 않는다.

## 로컬 HTML 스냅샷 사용 방침

- 사용자가 `docs/research/인명용한자.html`로 저장한 표에는 485개 독음 행이 있다. 열은 `한문 교육용 기초 한자`, `인명용 추가 한자 및 허용 한자 별표 1`, `별표 2`로 나뉜다.
- 파일 SHA-256은 `dd002dd18a8d6c66b102c6db582f927c0590c5f07b3c38c6eb67613b455c8081`이다. 2024년 대법원 보도자료의 추가 예시인 `㖀(률)`, `疋(아)`, `䬈(태)`가 모두 들어 있어 적어도 해당 추가분을 반영한 표임을 확인했다.
- 역색인 결과는 485개 독음, 9,111개 서로 다른 표기 글자, 9,360개 서로 다른 `(글자, 독음)` 후보이다. 대법원이 발표한 9,389자는 법적 허용 한자의 집계이고 이 파서의 수치는 이체자·복수 독음 단위가 섞인 후보 집계이므로 두 숫자가 같다고 가정하지 않는다.
- 이 파일은 나무위키 문서에서 저장한 표이므로 대법원 원문 자체로 간주하지 않는다. 최신성이나 법적 허용 여부의 최종 판정 자료로도 사용하지 않는다. 현재 T012에서는 사용자가 제공한 고정 입력 스냅샷과 후보 출처로만 사용한다.
- `scripts/build_name_readings.py`는 독음 중심 HTML 표를 한자 중심 `data/name-readings.json`으로 재현 가능하게 변환한다. JSON의 `characters`에서 `杜` 같은 글자가 바로 키가 되며, 값에는 독음과 기본·추가·이체자 구분 목록이 들어간다. 같은 글자·독음이 여러 열에 있으면 후보를 중복하지 않고 `kinds`에 출처 열을 함께 보존한다. 실행 시 사용하는 `scripts/name_readings.py`는 HTML을 직접 해석하거나 전체 표를 검색하지 않고 이 키로 조회한다.
- JSON은 생성 산출물이므로 직접 편집하지 않는다. HTML 원본이나 변환 규칙이 바뀌면 변환 명령을 다시 실행하며, 자동 테스트가 현재 HTML에서 같은 JSON이 생성되는지 비교한다.
- Unicode NFKC 정규화는 호환 한자의 조회 키에만 적용한다. OCR 원문과 DB 원문은 정규화한 글자로 덮어쓰지 않는다.
- 이름 첫 글자에서는 표의 지정음과 별도로 두음법칙 후보를 파생한다. 예를 들어 `李`는 표의 `리`와 파생한 `이`를 모두 내며, 파생 출처를 `initial_sound_law`로 표시한다. 후보만 추가하고 어느 음도 자동 확정하지 않는다.
- 목록 밖 글자는 오류가 아니라 `unregistered`로 반환한다. 고려·조선 시대 이름은 현대 목록 밖일 수 있으므로 후속 보충 사전이 필요하다.
- 후보와 검수 확정값을 분리한다. 조회 함수의 `confirmed_reading`은 항상 `null`이며 T012에서 자동 확정하지 않는다.

현대 출생신고 가능 여부를 판정해야 하는 기능에서는 [대법원 공식 조회](https://efamily.scourt.go.kr/cs/CsBltnWrtList.do?bltnbordId=0000010)를 최종 근거로 사용해야 한다. 이 프로젝트의 족보 독음 후보는 법적 등록 가능 여부 판정 기능이 아니다.

실행 예:

```bash
.venv/bin/python scripts/build_name_readings.py
.venv/bin/python scripts/name_readings.py 杜慶寧
```
