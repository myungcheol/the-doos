### 2026-11-10 — OCR 생몰 날짜를 구성 항목으로 보존

- **문제/원인:** 기존 생몰 필드는 OCR 원문 문자열과 양력 범위만 저장했다. 세로 열에서 `왕명·재위 연수·간지 첫 글자`와 `生`이 분리되면 OCR에 보이는 부분과 왕년으로 추론한 60갑자를 구분해 검수할 수 없었다. 왕년 없이 간지·월·일만 있는 사망 기록도 양력 변환 실패 시 구조화된 정보를 잃었다.
- **선택:** `birth_date`/`death_date`에 나라, 왕/연호, 재위 연수, 대응 서기, 60갑자, 음력 월·일·윤달을 선택적 항목으로 추가한다. 원문 간지 `sexagenary_ocr`와 왕년으로 보완한 `sexagenary_year`, 보완 출처를 별도로 저장한다. [국사편찬위원회 『고려사』 연표](https://db.history.go.kr/goryeo/level.do?levelId=kr_086_0010_0080&types=o)에서 목종 8년이 1005년 乙巳임을 대조했다. 첫 글자만 인식한 경우에도 보완값은 검토 대기이며 원문 판독을 확정값으로 바꾸지 않는다.
- **저장/호환성:** 기존 `birth_text`/`death_text`, `birth_solar`/`death_solar`, OCR 열·bbox, 검수 상태는 유지한다. 날짜 항목은 OCR 추출 초안과 검수 내보내기에 추가하고 PySide6·Streamlit 양쪽에서 개별 수정한다. 기존 수기 항목이 있으면 우선하며, 원문이 바뀌면 오래된 날짜 항목을 그대로 적용하지 않는다. 간지와 왕년이 충돌하면 양력 변환을 보류한다.
- **검증:** 합성 열과 저장된 001쪽 OCR 결과를 읽어 분리된 간지·생/졸 표식, 월·일 경계, 기존 출처 bbox를 확인했다. 날짜 항목의 Qt offscreen 표시·저장, 원문 수정 시 재계산, 검수 내보내기를 확인했다. 전체 단위 테스트 88개와 Python 컴파일 검사가 통과했다. 실제 OCR 모델 재추론 및 브라우저·실제 디스플레이 조작은 수행하지 않았다.
- **한계:** 왕년이 없는 간지 연도만으로 절대 서기를 확정하지 않는다. 왕명/연호 목록과 OCR 필드 경계가 불완전하면 일부 항목은 비어 있거나 추가 검수가 필요하다.
- **관련 커밋:** 이 기록을 포함한 커밋.

### 2026-11-10 — 생몰 음력 날짜의 양력 범위 초안과 재위 연도 조회

- **문제/맥락:** 출생·사망 원문은 왕/연호의 재위 연수와 음력 날짜로 적힌 경우가 많다. 기존 텍스트 필드만으로는 양력 날짜를 검색하거나 부분 날짜의 정밀도를 보존하기 어려웠다. 1000년 이전 기록도 있어 1000~2050년만 지원하는 `korean_lunar_calendar`로는 샘플의 975년을 처리할 수 없었다.
- **선택:** `historical_dates.py`에서 왕/연호 원년→서기와 음력→역산 그레고리력을 분리한다. `sxtwl==2.0.7`의 중국 천문 역법 모델을 사용하고, 존재하지 않는 음력 날짜를 다음 날짜로 넘기는 라이브러리 동작은 양력→음력 왕복 검사로 차단한다. 연·월·일이 부족하면 양끝을 포함하는 양력 구간을 `year`/`month`/`day` 정밀도와 함께 저장한다. OCR 자동 판독은 나라/왕·연호가 단일하게 식별되고 간지가 맞는 경우에만 검토 대기 초안으로 제안한다.
- **검수/호환성:** PySide6에는 나라·왕/연호·재위 연수·음력 월/일·윤달을 확인하는 대화상자를, Streamlit에는 대응 조회/변환 영역을 추가했다. 확인한 날짜에만 별도 `confirmed` 상태를 부여한다. 검증된 목록에 없는 왕/연호는 검수자가 원년과 마지막 서기 연도를 직접 입력할 수 있다. 기존 `birth_text`/`death_text`, OCR 근거, 검수 상태 형식은 보존하고 `birth_solar`/`death_solar`를 선택적 필드로 추가했다. 같은 OCR 출처의 원문이 바뀌어 날짜가 해제되면 레지스트리의 오래된 변환값도 제거하되, 다른 판본의 기존 날짜는 유지한다.
- **근거/한계:** [국사편찬위원회 『고려사절요』 왕년 대조](https://db.history.go.kr/goryeo/compareViewer.do?levelId=kj_%24s04)와 [조선왕조실록](https://sillok.history.go.kr/main.do)을 재위 연도 기준으로 삼았다. [975년 음력 10월 26일](https://db.history.go.kr/goryeo/itemLevelKrList.do?itemId=&levelType=&parentId=kr_002r_0570_0010&types=r)과 [1048년 음력 정월 1일](https://db.history.go.kr/goryeo/itemLevelKrList.do?itemId=kr&parentId=kr_007r_0040_0010&types=r)의 양력 날짜를 계산 결과와 대조했다. 중국 천문 모델과 현지 역사 달력 사이의 차이, OCR에서 배우자·타 사건의 날짜가 섞인 경우는 사람이 확인해야 한다. 목록은 전체 왕·연호를 포괄하지 않는다.
- **검증:** 합성·샘플 원문의 연호, 간지, 부분 날짜, 윤달, 불가능한 날짜, 원문 수정 후 저장/내보내기, Qt offscreen 변환 창과 기존 상태 보존을 단위 테스트로 확인했다. 실제 OCR 재추론과 브라우저·데스크톱에서의 수동 조작은 수행하지 않았다.
- **관련 커밋:** 이 기록을 포함한 커밋.

### 2026-11-10 — 이어진 페이지 원문의 필드별 초안

- **문제/원인:** `continuation_links`는 다른 페이지의 OCR 열·좌표를 보존했지만, 인물 검수 화면에는 연결 원문을 한 덩어리로만 표시했다. 검수자가 관직·생몰·묘소·배우자 문구를 다시 찾아 각 필드에 옮겨야 했다.
- **선택:** 확정된 연결의 세로 열을 원본 x좌표 순서로 읽고 기존 키워드 규칙을 확장해 필드별 초안을 계산한다. 표식 사이의 한 열은 같은 사건에 포함하고, 분류 근거가 없는 문장은 전체 `인물 기록` 초안에 남긴다. 데스크톱과 Streamlit 입력란에 기존 검수 값 다음으로 제안하며, 배우자 문구는 유형 미확정 항목으로 따로 제안한다. 연결 ID별 중복 표시와 검수자가 지운 제안의 재등장을 막는다. 새 연결이 있으면 정보 검수 상태를 다시 확인하도록 표시한다.
- **출처/절충:** 기존 `continuation_links` 형식과 원본 OCR 파일은 바꾸지 않는다. 내보내기의 `raw_data.field_ocr`에 연결 페이지·행·원본 열 bbox별 분류 근거를 추가한다. 검수자가 저장하기 전까지 확정된 인물 필드는 자동으로 바뀌지 않는다. 다른 페이지 bbox는 원래 페이지 이미지 위에 그리지 않는다.
- **검증:** 저장된 002쪽의 기존 두 연결을 읽어 첫 행의 관직·사망·묘소·배우자와 둘째 행의 관직·묘소 분류를 확인했다. 합성 열과 Qt offscreen 검수 화면에서 연결·재선택·저장·제안 삭제·bbox 보존을 확인했다. 전체 단위 테스트 74개와 관련 모듈 `compileall`이 통과했다. 실제 OCR 재추론과 데스크톱/브라우저 수동 조작은 수행하지 않았다.
- **한계:** OCR 표식이 없는 문장의 세부 의미, 앞 페이지에서 시작한 문장의 범주, 배우자가 동일인인지 여부는 규칙만으로 확정할 수 없다. 연결을 해제해도 이미 저장한 검수 문구는 자동 삭제하지 않는다.
- **관련 커밋:** 이 기록을 포함한 커밋.

### 2026-11-09 — 인물 정보 초안의 배우자·생몰 경계 수정

- **문제/원인:** 001쪽 한 인물의 출생·사망·묘소 초안에 배우자 생몰 기록이 반복되고, 배우자 근거 박스에는 앞선 가문 설명 열이 포함됐다. 기존 규칙이 모든 키워드 양옆 한 열씩을 무조건 포함하고, 열 ID로 근거를 다시 확장했다. 데스크톱 UI에는 배우자 OCR 초안 입력란도 없었다.
- **선택:** 첫 배우자 표식부터 인물 기록 끝까지를 배우자 구간으로 분리하고, 본인의 필드는 키워드별 필요한 앞/뒤 열만 사용한다. 사망과 매장이 한 OCR 열에 함께 있으면 초안 문구만 나누고 원본 열 bbox는 양쪽 근거에 그대로 둔다. 지명 유래의 `因號`를 인물의 호로 채우지 않는다. 데스크톱 화면은 배우자 원문 초안과 검수용 배우자 배열을 함께 보여 주며, 새 배열 항목은 유형 미확정·검토 대기로 둔다. 기존 수기 입력과 검수 상태는 우선한다.
- **검증:** 저장된 001쪽 OCR을 재추론 없이 읽어 해당 인물의 필드별 초안과 근거 열을 대조했다. 합성 회귀 테스트와 Qt offscreen 테스트를 포함한 전체 단위 테스트 69개, 관련 모듈 `compileall`이 통과했다. 실제 데스크톱 화면 조작과 새 OCR 추론은 수행하지 않았다.
- **한계:** 열 하나에 둘 이상의 사건이 있으면 근거 bbox를 글자 단위로 나누지 못한다. 배우자 구간 안에 다른 인물이나 주인공의 기록이 섞인 특수 판형은 별도 검수가 필요하다. 이미 저장한 잘못된 검수 값은 자동으로 덮어쓰지 않는다.
- **관련 커밋:** 이 기록을 포함한 커밋.

### 2026-11-09 — 높은 화면 확대율에서 스캔 표시 품질 개선

- **문제/원인:** 272%로 확대한 검수 이미지가 Windows 사진 미리보기보다 흐리게 보였다. 검수 UI는 원본 `QPixmap`을 `QGraphicsView`에서 부드럽게 확대했으며, 예시 스캔 `001.jpg`는 688×948픽셀이다.
- **선택:** 화면 배율이 100%를 넘으면 원본 배열을 Lanczos4로 2~4배 확대해 화면 표시용 픽스맵으로 캐시한다. 이미지 항목을 역배율로 축소해 장면 크기와 OCR bbox·선택 좌표를 원본 픽셀 기준으로 유지한다. 확대 결과는 1,200만 픽셀 이내로 제한한다. 선택 영역 OCR은 화면용 픽스맵이 아닌 원본 배열을 계속 사용한다.
- **검증:** Qt offscreen에서 272%일 때 688×948 원본이 2064×2844 화면용 이미지로 표시되고 장면 크기는 688×948로 유지됨을 확인했다. 회귀 테스트에서 3배 이미지의 좌표 역변환과 OCR용 원본 배열 불변을 확인했다. 실제 Windows 사진 미리보기와 동일한 보간·선명도를 보장하는 비교는 수행하지 않았다.
- **한계:** 원본 JPEG의 낮은 해상도나 압축 손실에서 사라진 글자 정보는 복원할 수 없다. 큰 스캔은 메모리 보호 상한 때문에 낮은 확대 배율을 선택할 수 있다.
- **관련 커밋:** 이 기록을 포함한 커밋.

### 2026-11-09 — 화면 확대율 표시와 영역 OCR 후보 복사

- **맥락/정정:** 양쪽 스캔의 실제 화면 배율을 알기 어려웠고, 앞선 선택 영역 OCR 기능은 후보를 이름 필드에 넣도록 제한했다. 이는 이름 외의 본문·관직에도 OCR 후보를 쓰려는 검수 흐름과 맞지 않았다.
- **선택:** 현재 쪽과 직전 쪽의 `QGraphicsView` 변환 배율을 각각 표시한다. `+`/`−`·화면 맞춤·`Ctrl+휠`로 달라진 실제 화면 배율을 읽는다. 후보를 더블클릭하거나 버튼을 누르면 한자 문자열만 클립보드로 복사하며 인물 필드는 변경하지 않는다.
- **OCR 경로:** 영역 선택은 원본 좌표로 기록하고, OCR은 화면 보간 결과가 아닌 원본 이미지 또는 저장된 ROI의 대응 픽셀을 잘라 실행한다. 기존 `run_name_ocr_variants`는 자른 영역을 3배 확대한 뒤 전처리를 적용한다. 확대는 인식에 도움을 줄 수 있지만 새 픽셀 정보를 만들지는 않는다.
- **검증:** Qt offscreen에서 배율 표시·후보 클립보드 복사·이름 필드 불변을 확인했다. 실제 PaddleOCR 추론과 Windows 사진 미리보기와의 시각 비교는 수행하지 않았다.
- **관련 커밋:** 이 기록을 포함한 커밋.

- **남은 문제/후속 작업:** 기존 비교 실행에서 생성한 PaddleOCR 결과는 `output/paddleocr` 경로로 계속 열 수 있다. 새 CLI에서는 이전 `--ocr-engine` 옵션을 제거했으므로 기존 실행 스크립트의 인자를 갱신해야 한다.
