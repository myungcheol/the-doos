### 2026-11-09 — 선택 영역 OCR 후보와 박스 숨기기

- **문제/맥락:** 작은 한자나 누락 인명을 원본에서 직접 지정해 재인식할 방법이 없었고, 기존 bbox가 영역 드래그를 방해했다.
- **해결/선택:** 두 이미지에 박스 숨기기와 영역 선택 모드를 추가했다. 선택 bbox는 원본 좌표로 유지하고, 표시 이미지가 ROI인 경우 오프셋을 뺀 부분만 잘라 기존 `run_name_ocr_variants`로 보낸다. 백그라운드 작업 스레드에서 PaddleOCR 모델을 재사용하고 전처리별 후보를 받아, 오른쪽 별도 탭에 중복을 정리한 한자 후보·점수·방식을 표시한다. 후보를 이름에 입력해도 인물 저장 전에는 검수 데이터가 바뀌지 않는다.
- **검증:** 합성 이미지의 오프셋·비오프셋 crop, Qt offscreen의 박스 숨김·드래그·비동기 결과 표시, 기존 OCR 함수 호출 및 검수 상태 불변을 회귀 테스트로 확인했다. 실제 PaddleOCR 모델 추론과 데스크톱 수동 조작은 수행하지 않았다.
- **한계:** 후보 점수는 OCR 내부의 상대 참고값이며 검증 확률이 아니다. 설치된 OCR 엔진과 모델이 필요하다.

### 2026-11-09 — 이어진 OCR 영역 표시와 개별 페이지 자동 검색

- **문제/원인:** 통합 `ocr_results.json`에는 002쪽만 들어 있었고 001쪽 결과는 `output/001/`에 따로 남아 있었다. 데스크톱은 통합 목록만 페이지 선택기에 넣어 001쪽으로 이동할 수 없었다. 이어진 기록은 OCR 열을 낱개로 표시해 실제 위치와 연결할 원문 범위를 파악하기 어려웠다.
- **해결:** 같은 결과 폴더의 개별 `rows.json`·인물·관계 파일을 읽고 통합 결과의 스캔 경로를 기준으로 원본을 찾아 페이지 번호순으로 표시한다. 재검색 버튼은 현재 페이지를 유지한다. 검색은 검수 상태에 임시 페이지를 저장하지 않는다. 인접한 미배정 OCR 열은 32px 이하의 가로 빈틈을 기준으로 화면에서 묶고, 영역의 원본 좌표와 OCR 앞부분 및 전체 원문을 표시한다. 연결 시 원래 열별 bbox·token·confidence를 그대로 보존하며 확정 연결의 열은 다시 제안하지 않는다.
- **절충/한계:** 영역 묶음은 위치 기반 제안일 뿐 인물 소유를 판정하지 않는다. 스캔을 찾지 못한 개별 페이지는 목록에 넣지 않고 상태 표시줄에 이유를 알린다. 실제 디스플레이에서 사람이 클릭하는 검증과 새 OCR 추론은 수행하지 않았다.
- **검증:** 단위 테스트 62개와 관련 Python `compileall` 통과. Qt offscreen에서 실제 `output/`을 읽어 001·002쪽 이동, 002쪽 첫 행의 OCR 17열이 한 영역으로 표시됨, 검수 상태·레지스트리·원본 OCR 파일 해시 불변을 확인했다.
- **관련 커밋:** 이 기록을 포함한 커밋.

### 2026-11-09 — OCR 선택 UI 재수정, 페이지 계속 기록, 분리 획 인명 복구

- **문제:** 이전 popup 타이밍 수정 후에도 실제 사용자 환경에서 OCR 강조 펼침 목록이 닫히지 않았다. 002쪽 첫 행에는 001쪽 인물의 계속 기록과 새 이름이 함께 있었으며 새 이름 영역은 검출되지 않았다. 현재 통합 OCR JSON에는 002쪽만 있었지만 001쪽 개별 결과는 남아 있었다.
- **원인/선택:** OCR 강조를 popup 없는 고정 버튼으로 바꾸고 줌 도구를 이미지 위로 이동했다. 새 이름의 두 번째 글자가 세로로 분리된 획으로 검출돼 높이 기준을 통과하지 못했다. 가까운 위·아래 획을 합치되 폭을 제한한다. 폭 제한 없는 첫 접근은 001쪽 1행 본문 두 곳을 인명으로 오인해 채택하지 않았다.
- **데이터 모델:** 기존 OCR 파일을 보존하고 검수 상태에 `additional_people`, 명시적으로 불러온 `supplemental_pages`, 검수자가 선택한 열의 `continuation_links`를 추가한다. 같은 행의 직전 페이지 마지막 인물은 제안만 하며 자동 연결하지 않는다. 이름 있는 행의 오른쪽 부분도 선택 가능하고, 확정된 계속 기록을 통해 여러 페이지를 연결할 수 있다. 해제는 거절 상태를 남긴다.
- **출처/호환성:** 연결 대상 영구 UID와 원문 페이지·행·열·원본 bbox·token/confidence를 저장하며 원문을 복사해 사람이 쓴 전기를 덮어쓰지 않는다. 내보내기의 `raw_data.record_ocr.continuations` 및 추가 출처로 보존한다. 데스크톱과 Streamlit의 내보내기는 이 확장을 함께 읽는다. 개별 관계 JSON의 누락된 `source_page`는 검수자가 지정한 원본 페이지로 보충한다.
- **검증:** `.venv/bin/python -m unittest discover -s tests -v` 58개 통과 및 관련 모듈의 `compileall` 통과. 합성 데이터의 버튼 선택, 이전 결과 불러오기·저장·복원, 기록 연결/해제, 원본/UID 보존, 분리 획 및 ROI 오프셋을 확인했다. 실제 001/002쪽의 저장된 12행을 검출 함수만으로 비교해 기존 행의 후보 수를 유지하면서 002쪽 1행 후보 1개를 추가했다. Qt offscreen에서 실제 002쪽과 이전 페이지 제안 배치를 렌더링했으며 저장 함수를 비활성화하고 검수 상태/레지스트리 해시가 불변임을 확인했다. OCR 모델 추론과 실제 디스플레이 수동 테스트는 수행하지 않았다.
- **한계:** 미배정 열에는 잡음·인명 누락이 있을 수 있으므로 자동 귀속시키지 않는다. 검출 튜닝은 두 샘플에 한정됐고 다른 판본의 정확도는 검증하지 않았다. 기존 OCR을 재생성할 경우 추가 검수 후보와 중복 여부를 사람이 확인해야 한다.

### 2026-11-09 — Qt 입력기 경로와 OCR 선택, 성별 검수

- **문제/원인:** OpenCV Linux wheel이 import 중 `QT_QPA_PLATFORM_PLUGIN_PATH`와 `QT_QPA_FONTDIR`을 자체 경로로 변경한다. 이 경로에는 Qt 입력기 플러그인이 없어 PySide6의 입력기 탐색을 방해할 수 있다. 확인 환경에는 IBus/Fcitx 실행 파일도 없었다. OCR 선택 시 popup 처리 중 이미지 장면을 다시 그리는 타이밍도 문제 후보였다.
- **수정:** OpenCV가 설정한 경로만 이전 사용자 설정으로 복원하고 OCR 선택에 따른 장면 갱신을 이벤트 루프 다음 차례로 미룬다. 원문 子/女 표식과 별도의 검수 성별을 저장하며 Streamlit 저장도 기존 성별 값을 보존한다.
- **검증/한계:** Qt offscreen의 popup 클릭과 합성 입력기 이벤트, 성별·원문·기존 데이터 보존 테스트를 실행한다. 실제 IBus/Fcitx 한글 조합 및 한자 변환은 입력기가 없는 환경이라 검증하지 못했다.
- **관련 커밋:** 이 기록을 포함한 커밋.

### 2026-11-09 — PySide6 데스크톱 검수 UI 추가

- **맥락:** 기존 Streamlit UI를 유지하면서 별도의 데스크톱 검수 창을 제공한다.
- **선택:** PySide6 화면에서 기존 검수 상태 및 내보내기 함수를 사용해 JSON 형식을 공유한다. 저장은 명시적이며, 파일 해시로 외부 검수 상태 변경을 감지한다. 이미지와 OCR 좌표는 원본 좌표를 사용하고 ROI 대체 이미지에는 오프셋을 적용한다.
- **절충:** 초기 화면은 인물 편집과 관계 승인·거절·수동 연결을 지원한다. 공용 레지스트리 갱신, 기존 UID 선택, 판본 메타데이터 편집, 관계 후보의 인물 교체와 되돌리기는 기존 Streamlit에서 수행한다. Streamlit 함수를 공유하므로 데스크톱 의존성에도 Streamlit이 필요하다.
- **검증:** 임시 합성 OCR 결과와 Qt offscreen 테스트로 첫 화면, 저장 호환성, 기존 데이터 보존, 외부 수정 충돌, 수동 관계 중복을 확인한다. 실제 디스플레이 상호작용과 OCR 모델 추론은 별도 검증이 필요하다.
- **관련 커밋:** 이 기록을 포함한 커밋.

### 2026-11-09 — 검수 UI OCR focus 첫 렌더링 오류 수정 (과거 작업 요약)

- **문제:** 인물을 선택하지 않은 첫 화면에서 `UnboundLocalError: cannot access local variable 'focus'`가 발생함.
- **원인:** `focus`가 `selected_for_overlay` 조건 안에서만 할당됐지만, 이미지 뷰어 payload에는 무조건 전달됨.
